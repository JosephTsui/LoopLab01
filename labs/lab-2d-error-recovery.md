# Lab 2-D：故意製造錯誤並觀察恢復

**完成時間：** 2026-06-15

---

## 實驗 A — 工具失敗：讀取不存在的檔案

**指令：** 讀取 `labs/nonexistent-file.md`

**結果：**
```
File does not exist. Note: your current working directory is D:\LoopLab\LoopLab01
```

**觀察：**
- 工具回傳錯誤訊息，流程未中斷
- 沒有自動嘗試替代方案（因為沒有提供替代目標）
- Agent 收到錯誤後可以選擇：回報給使用者、嘗試其他路徑、或繼續後續步驟

**結論：** 工具失敗不會崩潰，錯誤以訊息形式回傳給 Agent，由 Agent 決定如何處理。

---

## 實驗 B — 矛盾指令：寫入不存在的目錄

**指令：** 讀取所有 `.js` 檔案，存入 `labs/output/results.md`（目錄不存在）

**結果：** `File created successfully at: D:\LoopLab\LoopLab01\labs\output\results.md`

**觀察：**
- Write 工具**自動建立**不存在的父目錄 `labs/output/`
- Agent 完全不需要感知「目錄不存在」這個問題
- 工具框架本身處理了矛盾，對 Agent 透明

**對比實驗 A：**
| 情境 | 處理方式 |
|------|---------|
| 讀取不存在的檔案 | 回傳錯誤，Agent 需處理 |
| 寫入不存在的目錄 | 工具自動建立目錄，透明處理 |

**結論：** 不同工具對「前置條件不滿足」的處理策略不同。Loop Engineer 需要了解每個工具的行為邊界。

## 實驗 C — 驗證機制：生成程式碼並自我驗證

**指令：** 生成 `sumArray()` 函式，實際執行驗證三個測試案例

**子代理行為（2 次工具呼叫）：**
1. Write — 將生成的程式碼寫入 `sumArray.js`
2. Bash(node) — 實際執行 Node.js 跑測試

**生成的程式碼：**
```javascript
function sumArray(arr) {
  if (!Array.isArray(arr)) return 0;
  return arr.reduce((sum, item) => {
    return typeof item === 'number' && !isNaN(item) ? sum + item : sum;
  }, 0);
}
```

**測試結果：**
| 測試案例 | 期望值 | 實際結果 | 狀態 |
|---------|--------|---------|------|
| `[1, 2, 3]` | 6 | 6 | ✅ PASS |
| `[]` | 0 | 0 | ✅ PASS |
| `[1, 'a', 2]` | 3 | 3 | ✅ PASS |

**觀察：**
- 子代理不只「聲稱」程式碼正確，而是**實際執行**後回報真實結果
- 驗證循環：生成 → 寫檔 → 執行 → 觀察結果 → 回報
- 這是 Agent Loop 自我修正能力的基礎

## 三實驗總結

| 實驗 | 失敗類型 | Agent 行為 | 關鍵學習 |
|------|---------|-----------|---------|
| A | 工具回傳錯誤 | 收到錯誤訊息，流程不崩潰 | 錯誤是可處理的訊號，不是例外 |
| B | 前置條件不滿足 | 工具自動修復，Agent 無感 | 了解工具邊界比防禦性程式碼更重要 |
| C | 自我驗證 | 實際執行而非推斷 | 真正的驗證需要觀察，不只是思考 |

## Loop 的四大失敗模式（對照課程）

| 失敗類型 | 本實驗對應 | 結論 |
|---------|-----------|------|
| 工具失敗 | 實驗 A | 錯誤訊息可被捕捉並處理 |
| 無限迴圈 | 未觸發 | 需設置最大迭代數保護 |
| 上下文溢出 | 未觸發 | 大量讀取時需壓縮或分段 |
| 幻覺結果 | 實驗 C | 驗證步驟能有效阻止「假完成」 |
